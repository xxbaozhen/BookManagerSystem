# BookManagerSystem

## 1. 项目简介

BookManagerSystem 是一个基于 **Godot 4.7 .NET** 开发的 Windows 桌面端图书管理系统。

项目主要用于管理图书、用户以及图书借阅相关数据，并提供直观的桌面管理界面。  

当前项目处于 **UI 框架搭建阶段**，核心业务逻辑和数据库功能尚未开始实现。

---

## 2. 项目目标

最终实现一个完整的桌面端图书管理系统，主要包含：

- 用户管理
- 图书管理
- 图书分类管理
- 图书借阅与归还
- 借阅记录查询
- 数据统计
- 系统设置
- 用户登录与权限管理

项目重点：

- 界面简洁、现代
- 操作直观
- 功能模块清晰
- UI 与业务逻辑解耦
- 数据层与 UI 解耦
- 便于后续维护和扩展

## 6. 架构规划

项目希望保持 UI、业务逻辑和数据层之间的解耦。

初步规划：

```text
UI
 │
 ▼
View / UI Logic
 │
 ▼
Service
 │
 ▼
Repository / Data Access
 │
 ▼
SQLite
```

职责大致如下：

### UI

负责：

- 显示数据
- 用户输入
- UI 状态
- 动画
- 页面切换

不直接处理复杂业务逻辑。

### Service

负责：

- 业务规则
- 借阅逻辑
- 用户逻辑
- 图书逻辑
- 数据验证

### Repository

负责：

- 数据库访问
- CRUD
- SQL 查询

### SQLite

负责：

- 持久化数据

## 7. 项目结构规划

当前结构会随着项目开发逐步调整。

目标结构大致：

```text
Src/
├── core/
│   ├── models/
│   ├── services/
│   └── repositories/
│
├── global/
│
└── ui/
    ├── components/
    └── views/
```

其中：

- `core/`：核心业务与数据相关代码
- `global/`：全局状态和工具
- `ui/components/`：可复用 UI 组件
- `ui/views/`：具体页面

实际结构以开发过程中验证后的方案为准，不强制一次性完成。

## 9. 开发原则

### 9.1 UI 与业务逻辑分离

UI 不应该直接承担复杂业务逻辑。

### 9.2 小步开发

每次只实现一个明确的功能，并保持 Git 提交清晰。

### 9.3 优先简单可靠

没有实际需求时，不引入复杂的设计模式或第三方依赖。

### 9.4 不过早设计

当前没有必要确定的架构细节，在真正开发到对应功能时再确定。

### 9.5 文档与代码同步

当项目的重要设计发生变化时，同时更新相关 Markdown 文档。
